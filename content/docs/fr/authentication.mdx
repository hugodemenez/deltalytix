## Obtenir un jeton

Vous pouvez générer ou coller un jeton depuis n’importe quel panneau d’essai, au moment où vous en avez besoin.

<DocsGetTokenButton />

Deltalytix est son propre serveur d’autorisation OAuth 2.0. Les humains se connectent toujours via Supabase ; les jetons API sont émis et validés par Deltalytix.

Chaque requête `/api/v1/*` exige un jeton Bearer :

```http
Authorization: Bearer dltx_at_…
```

Les endpoints REST sont servis depuis `https://www.deltalytix.app` sous **API v1** (`/api/v1/*`). Les listes acceptent `limit` (défaut `100`, max `500`) et `cursor`. Les timestamps sont en ISO 8601. Découverte machine-readable : [`/openapi.json`](/openapi.json), [`/.well-known/openid-configuration`](/.well-known/openid-configuration), [`/.well-known/oauth-protected-resource`](/.well-known/oauth-protected-resource).

### Formats de jetons

Les jetons sont des chaînes opaques. Deltalytix ne stocke que des empreintes SHA-256.

| Type | Préfixe | Durée de vie |
| --- | --- | --- |
| Access token | `dltx_at_<48 hex chars>` | 3600 secondes |
| Refresh token | `dltx_rt_<48 hex chars>` | 30 jours (rotation à chaque usage) |
| Personal access token (PAT) | `dltx_pat_<48 hex chars>` | Pas d’expiration jusqu’à révocation |
| Client ID | `dltx_app_<24 hex chars>` | — |
| Client secret | `dltx_secret_<48 hex chars>` | Affiché une seule fois à la création |

### Scopes

Demandez uniquement les scopes dont votre intégration a besoin. Séparez-les par des espaces dans le paramètre OAuth `scope`. La liste complète est dans [ce que vous pouvez faire](#ce-que-vous-pouvez-faire).

### Personal access tokens

Les PAT conviennent aux scripts et outils privés. Créez-les et révoquez-les depuis les paramètres développeur du tableau de bord, en choisissant les scopes nécessaires. La valeur du jeton n’est affichée qu’une fois.

```bash
curl https://www.deltalytix.app/api/v1/me \
  -H "Authorization: Bearer dltx_pat_YOUR_TOKEN"
```

### Token démo

Le playground de la documentation peut émettre un token démo de courte durée, en lecture seule, sans connexion. Il authentifie un compte d’exemple partagé (`DEMO-001`) pour essayer les routes `GET`. Les scopes d’écriture exigent votre propre token docs ou PAT.

## OAuth 2.0

### 1. Autoriser

Envoyez l’utilisateur vers la page de consentement (HTML). Les utilisateurs non authentifiés sont redirigés vers `/authentication?next=…`.

```http
GET /oauth/authorize
  ?client_id=dltx_app_…
  &redirect_uri=https%3A%2F%2Fyour-app.example%2Fcallback
  &response_type=code
  &scope=profile%3Aread%20trades%3Aread
  &state=csrf-token
  &code_challenge=BASE64URL_SHA256_OF_VERIFIER
  &code_challenge_method=S256
```

<DocsEndpointTry method="GET" path="/oauth/authorize" />

| Query | Requis | Notes |
| --- | --- | --- |
| `client_id` | Oui | Application OAuth enregistrée |
| `redirect_uri` | Oui | Doit correspondre exactement à une URI enregistrée |
| `response_type` | Oui | Doit être `code` |
| `scope` | Oui | Scopes séparés par des espaces |
| `state` | Recommandé | Protection CSRF ; renvoyé à la redirection |
| `code_challenge` | Recommandé | Challenge PKCE S256 |
| `code_challenge_method` | Avec challenge | Doit être `S256` |

En cas d’approbation, Deltalytix émet un code d’autorisation à usage unique (TTL de 10 minutes) et redirige :

```text
https://your-app.example/callback?code=…&state=…
```

En cas de refus :

```text
https://your-app.example/callback?error=access_denied&state=…
```

### 2. Échanger le code contre des jetons

`POST /api/oauth/token` accepte du form-urlencoded ou du JSON.

<DocsEndpointTry method="POST" path="/api/oauth/token" />

```bash
curl -X POST https://www.deltalytix.app/api/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "code=AUTHORIZATION_CODE" \
  -d "redirect_uri=https://your-app.example/callback" \
  -d "client_id=dltx_app_…" \
  -d "code_verifier=PKCE_VERIFIER"
```

Les clients confidentiels peuvent envoyer `client_secret` à la place (ou en plus) de PKCE, selon l’enregistrement de l’application.

<DocsResponse tone="success" label="Succès">

```json
{
  "access_token": "dltx_at_…",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "dltx_rt_…",
  "scope": "profile:read trades:read"
}
```

</DocsResponse>

Les erreurs OAuth suivent la RFC 6749 :

<DocsResponse tone="error" label="Erreur">

```json
{
  "error": "invalid_grant",
  "error_description": "Authorization code is invalid or expired"
}
```

</DocsResponse>

### 3. Appeler l’API

```bash
curl https://www.deltalytix.app/api/v1/trades?limit=10 \
  -H "Authorization: Bearer dltx_at_…"
```

```js
const res = await fetch("https://www.deltalytix.app/api/v1/trades?limit=10", {
  headers: {
    Authorization: `Bearer ${accessToken}`,
  },
});
```

### 4. Rafraîchir l’access token

```bash
curl -X POST https://www.deltalytix.app/api/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "refresh_token",
    "refresh_token": "dltx_rt_…",
    "client_id": "dltx_app_…",
    "client_secret": "dltx_secret_…"
  }'
```

Les refresh tokens tournent à chaque usage. Conservez le nouveau `refresh_token` de chaque réponse réussie.

Les clients publics ayant obtenu des jetons via PKCE peuvent rafraîchir sans client secret lorsque c’était le mode d’émission d’origine.

### 5. Révoquer un jeton

```bash
curl -X POST https://www.deltalytix.app/api/oauth/revoke \
  -H "Content-Type: application/json" \
  -d '{
    "token": "dltx_at_…",
    "client_id": "dltx_app_…",
    "client_secret": "dltx_secret_…"
  }'
```

<DocsEndpointTry method="POST" path="/api/oauth/revoke" />

La révocation renvoie toujours `200`, que le jeton ait été trouvé ou non.

### Échecs côté resource server

Un Bearer manquant ou invalide renvoie `401` :

<DocsResponse tone="error" label="Erreur">

```json
{
  "error": "unauthorized",
  "message": "…"
}
```

</DocsResponse>

avec un en-tête `WWW-Authenticate` pointant vers les métadonnées de ressource protégée.

Un jeton valide sans le scope requis renvoie `403` :

<DocsResponse tone="error" label="Erreur">

```json
{
  "error": "insufficient_scope",
  "message": "…"
}
```

</DocsResponse>

### Gérer les applications et les jetons

Dans les paramètres développeur du tableau de bord, vous pouvez :

- Créer des applications OAuth (nom, redirect URIs, scopes autorisés) — `client_id` toujours visible ; `client_secret` affiché une fois
- Créer et révoquer des personal access tokens avec les scopes choisis — la valeur du PAT est affichée une fois
