Le serveur MCP est un endpoint HTTP streamable à l’adresse `https://www.deltalytix.app/api/mcp`. Il parle le Model Context Protocol et appelle les mêmes fonctions serveur que les routes de lecture sous `/api/v1`. Chaque outil est limité à l’utilisateur propriétaire du jeton bearer.

Le serveur est sans état. Envoyez un message JSON-RPC par `POST`. Les réponses sont en `application/json` (pas un flux SSE maintenu ouvert). `GET` et `DELETE` répondent 405.

## Authentification

Envoyez le même jeton bearer que l’API REST :

```http
Authorization: Bearer dltx_pat_…
```

Deux types de jetons fonctionnent :

- Un **personal access token** depuis [Paramètres → Connexions](/fr/dashboard/settings#connections). Choisissez les scopes de lecture dont les outils ont besoin. La valeur n’est affichée qu’une fois. C’est le chemin que Claude, ChatGPT, Cursor et Grok peuvent utiliser aujourd’hui.
- Un **access token OAuth** issu du flux authorization code sur `/oauth/authorize`, avec PKCE `S256`. Le jeton et le refresh token sont les mêmes enregistrements que l’API REST. Révoquer l’application dans Paramètres → Connexions pose `revokedAt`, et l’appel MCP suivant est refusé.

Un jeton absent, inconnu, expiré ou révoqué renvoie HTTP 401. L’en-tête `WWW-Authenticate` indique `resource_metadata` pour ce serveur :

```http
WWW-Authenticate: Bearer realm="mcp", resource_metadata="https://www.deltalytix.app/.well-known/oauth-protected-resource/api/mcp"
```

Ce document pointe `authorization_servers` vers Deltalytix. Le client lit ensuite [`/.well-known/oauth-authorization-server`](/.well-known/oauth-authorization-server) pour les endpoints d’autorisation, de jeton et de révocation, et pour `code_challenge_methods_supported: ["S256"]`.

### Enregistrement dynamique de client

`POST /oauth/register` (RFC 7591) est annoncé comme `registration_endpoint`. Claude, ChatGPT et Cursor enregistrent un **client public** (`token_endpoint_auth_method: none`) et doivent utiliser PKCE S256. Les URI de redirection sont exactes : `https`, ou `http` sur `localhost`, `127.0.0.1` ou `[::1]`. Les jokers sont refusés. Cela couvre :

- `https://claude.ai/api/mcp/auth_callback` et le callback loopback de Claude Code
- `https://chatgpt.com/connector_platform_oauth_redirect` et `https://chatgpt.com/connector/oauth/{callback_id}`
- `https://www.cursor.com/agents/mcp/oauth/callback` et `http://localhost:8787/callback`

L’enregistrement est limité à 10 requêtes par heure et par adresse. L’écran de consentement affiche le nom du client, les scopes demandés et **Changer de compte**. Après autorisation, Paramètres → Connexions liste ce client par son nom et permet de le révoquer. Un personal access token reste possible si vous ne voulez pas d’OAuth.

Les applications créées sur la [page Développeurs](/fr/dashboard/developers) restent des clients confidentiels avec un client secret. PKCE reste recommandé pour eux et obligatoire pour les clients publics. Les réponses d’autorisation incluent `iss` (RFC 9207). Un jeton émis avec `resource` égal à l’URL MCP (RFC 8707) n’est accepté que sur `/api/mcp`.

### Scopes

Les outils vérifient les scopes du jeton. Un jeton qui peut appeler `get_profile` ne peut pas appeler `list_trades` sans `trades:read`. L’appel renvoie une erreur d’outil et ne lit aucune donnée.

| Outil | Scope | Route REST |
| --- | --- | --- |
| `get_profile` | `profile:read` | `GET /api/v1/me` |
| `list_accounts` | `accounts:read` | `GET /api/v1/accounts` |
| `list_trades` | `trades:read` | `GET /api/v1/trades` |
| `get_metrics_summary` | `metrics:read` | `GET /api/v1/metrics/summary` |
| `get_account_metrics` | `metrics:read` | `GET /api/v1/metrics/accounts` |
| `get_equity_curve` | `metrics:read` | `GET /api/v1/metrics/equity` |
| `get_daily_pnl` | `metrics:read` | série quotidienne de `GET /api/v1/metrics/equity` |
| `list_connections` | `connections:read` | `GET /api/v1/connections` |

Un jeton en lecture seule doit demander `profile:read trades:read accounts:read connections:read metrics:read`.

`list_trades` utilise `limit` (défaut 100, maximum 500) et `cursor`. `get_equity_curve` et `get_daily_pnl` utilisent `limit` (défaut 366, maximum 1000) et `cursor`. Aucun outil n’accepte d’identifiant utilisateur. `list_connections` ne renvoie pas les jetons courtier.

Les outils d’écriture (créer des trades, importer un fichier, créer ou synchroniser une connexion courtier) ne sont pas exposés. Utilisez l’API REST pour cela, avec le scope d’écriture correspondant.

### Révoquer l’accès

Paramètres → Connexions liste les personal access tokens et les applications OAuth que vous avez autorisées. Révoquez l’un ou l’autre ici. Le serveur MCP lit la même table de jetons : un jeton révoqué cesse de fonctionner à la requête suivante. Il n’y a pas de liste séparée de clients MCP.

## Connexion

### Cursor

Un clic installe le serveur et lance OAuth (enregistrement dynamique, PKCE) :

[Ajouter Deltalytix à Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=deltalytix&config=eyJ1cmwiOiJodHRwczovL3d3dy5kZWx0YWx5dGl4LmFwcC9hcGkvbWNwIn0%3D)

Ou placez ceci dans `~/.cursor/mcp.json` et laissez Cursor vous connecter :

```json
{
  "mcpServers": {
    "deltalytix": {
      "url": "https://www.deltalytix.app/api/mcp"
    }
  }
}
```

Un personal access token fonctionne encore si vous définissez `headers.Authorization` à `Bearer dltx_pat_…` au lieu de vous connecter.

### Claude

Dans Claude, ajoutez un connecteur personnalisé et indiquez l’URL `https://www.deltalytix.app/api/mcp`. Claude s’enregistre, vous envoie sur l’écran de consentement Deltalytix et conserve le jeton. Vous ne collez pas de client id.

Un personal access token fonctionne encore comme en-tête :

```http
Authorization: Bearer dltx_pat_YOUR_TOKEN
```

### ChatGPT

Dans les réglages des connecteurs, ajoutez un serveur MCP avec l’URL `https://www.deltalytix.app/api/mcp`. ChatGPT enregistre un client public et ouvre l’écran de consentement. La réponse d’autorisation contient `iss`, donc ChatGPT peut utiliser son URI de redirection stable. Un personal access token reste disponible comme credential bearer si vous ne voulez pas d’OAuth.

### Grok et les autres clients

Tout client qui implémente le HTTP streamable peut `POST` vers `https://www.deltalytix.app/api/mcp` avec :

- `Authorization: Bearer dltx_pat_YOUR_TOKEN`
- `Accept: application/json, text/event-stream`
- `Content-Type: application/json`
- `MCP-Protocol-Version: 2025-06-18` sur chaque requête après `initialize`

Découverte pour le client : [`/.well-known/mcp/server-card.json`](/.well-known/mcp/server-card.json).
